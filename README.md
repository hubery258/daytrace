# 日迹

日迹 / daytrace 用于管理待办、安排日程、记录实际时间和每日日志。

使用方法见下方[用户手册](#用户手册)，包含日常记录、手动设备合并和备份恢复。

当前版本号：**v0.11.3**。保留 v0.11.2 的显示名称、计划参考层和首页日程改进；v0.11.3 重新设计手动设备数据合并：完成优先、字段冲突选择、实际时间冲突区间选择、日志整理及事务写入。实体机矩阵和签名 release 仍是 v1.0.0 前的发布门槛。

v0.11.3 专项复查补齐了拆分时间块的双向版本识别、本机关联断裂检查和重复例外 UUID 优先更新；旧预览在数据包、选择、模式或本地数据变化后禁止执行。Windows portable 与 Android debug APK 已重新打包，包含全部复查修复；构建校验值见 release/build-info-0.11.3.json。

## 用户手册

适用于 v0.11.3。在应用的“设置”顶部点击“用户手册”即可展开阅读全文，无需联网。数据保存在本机；设备之间需要手动传递并合并数据。DDL 是截止日期，提前提醒在页面内显示，没有系统通知。

### 安排并记录一天

以“课程报告”为例：上午写初稿，下午校对，晚上回顾。

1. 在“项目”新建“课程报告”，进入项目，新建“写初稿”和“校对”两个待办。按需要设置 DDL、分类和状态；设为“关注中”的待办可在首页查看，等同学反馈时可设为“等待答复”。项目内手动顺序数字越小越靠前，已设顺序的任务排在自动排序任务之前。
2. 在“日程”安排上午 09:00–10:00 写初稿的计划，关联“写初稿”。计划只表示安排，不会自动生成实际时间或进入统计。
3. 实际开始写作时，在“计时”填写事项并关联“写初稿”，点击“开始计时”；休息时暂停，回来后继续。结束时选择属性并点击“结束并记录”。每格有效计时覆盖至少一半才折算为实际时间块；15 分钟格需至少 7 分 30 秒，30 分钟格需至少 15 分钟。计时不会覆盖手动记录，遇到已有计时块时仅在新计时覆盖更长时替换。取消计时不生成实际记录，也不保留本次时长。
4. 需要补录或修正时，在“日程”的实际时间块视图点选一格或拖选一段，再点属性。选区已有记录会被替换；“清空”移除选区记录。“详情”可填写备注、关联待办或项目。关联待办后，项目跟随该待办。属性、颜色和 15/30 分钟粒度在“设置”调整。
5. 初稿完成后勾选待办。下午用同样方式记录校对时间。两个待办都完成后，项目仍需手动设为完成。
6. 晚上在“日志”写下当天记录并保存，页面列出当天完成的待办。历史日期可查看，正文只能编辑今天。“统计”可按日、周、年或自选范围查看实际投入，并按属性、待办、项目汇总；占比以已记录时间为分母，不代表全天占比。

重复事项可在新建待办或计划时勾选重复，填写频率、开始日期及需要的结束日期。删除时，确认框的“取消”只删除当前实例；“确定”会停止规则，并删除未来未完成待办或未来计划实例，请核对影响范围。

### 用 AI 生成草稿

仍以课程报告为例：在“设置 → AI 辅助”填写 API Key、兼容 OpenAI 的 API 地址和模型名，保存后打开“AI 新建”，输入“为课程报告创建明天下午两点校对一小时的计划”。若出现澄清问题，回答后再生成。

在草稿确认窗口检查名称、日期、项目和备注，拒绝不需要的条目或修改后点击“确认创建”。仅接受的草稿会写入待办或日程。日志页也可根据当天记录生成明日建议，项目页可生成下一步草稿。

请求及相关上下文发送到你配置的 AI 服务；Key 不提交给日迹后端。当前设置页将 Key 保存在本机浏览器存储中，JSON 数据包不包含它。草稿报错时，可展开 AI 原文检查或复制错误信息。

### 在电脑和手机之间手动合并

假设两端都已升级到 v0.11.3，并通过同一份 JSON 数据包拥有“课程报告”及两个待办。先导入共同的初始数据，再分开记录；在两端分别新建同名任务，会被视为不同任务。

上午在电脑完成“写初稿”，记录 09:00–10:00；下午在手机完成“校对”，记录 14:00–15:00。晚上将手机数据汇总到电脑：

1. 手机在“设置 → 本地数据 → 数据导入导出”点击“导出 JSON”，保存或分享文件。
2. 电脑选择“合并设备数据”，点击“选择 JSON 导入”，打开手机文件。查看新增、变更、跳过和冲突数量；此时尚未写入本机数据。
3. 若同一待办的备注不同，比较“本机”和“导入”，选择保留哪份，或在编辑框整理后确认；空白值也可被选中。计划日程冲突按整条选择，日志正文可选一份或手动整理，不会自动拼接。
4. 两段时间没有重叠时会同时保留。若手机还补录了 09:30–10:30，且与电脑记录冲突，按预览选择 09:30–10:00 使用哪一边；双方不冲突的部分仍保留。同一记录被移动或修改时，应选择其一个版本。展开“时间块影响”查看拆分或替换范围。
5. 解决所有冲突后点击“确认合并导入”，核对确认框再执行。写入前会保存并校验本机副本；副本失败或预览过期时不能执行，应重新预览。
6. 合并后，电脑保留上午与下午的记录，两个待办均为完成。再从电脑导出合并结果，让手机以“合并设备数据”导入，手机才会得到相同结果。

必要限制：

- 一边完成就保留完成；两边均完成时取较早的有效完成时间。缺少有效日期时需指定。删除和取消完成不会传播，旧设备仍已完成时再次合并可能恢复完成。
- 批量“保留本机 / 使用导入”只处理当前所选范围内的剩余普通冲突；属性改名、完成日期、活动计时和旧包任务关联需单独确认。
- 同名但不同身份的属性需改名，保留两项。多条活动计时需选一条作为当前计时，其余暂存暂停；没有当前计时时，可在“最近计时”继续其他条目。
- 旧包仅有源设备任务编号时，需重新选择关联任务，也可明确确认无关联。支持合法的 0.6.0、0.8.0 和 0.10.0 数据包；旧实际日程会跳过，不会转为时间块。
- 重复导入不会自动追加日志；旧差异仍可能再次要求选择。执行结果未确认时，先检查本机数据再重新预览，操作可能已完成。

#### 改用 WebDAV 传递同一份数据

在两端“设置 → WebDAV 同步”填写自己的服务器、用户名、密码和已存在的远程目录，测试连接并保存。测试可能创建缺失目录，并写入后删除临时探测文件。默认远端文件是 `daytrace-latest.json`，可在高级选项修改；上传会覆盖当前配置的文件。

接着用 WebDAV 完成上面的课程报告汇总：

1. 若远端已有电脑上午的数据，手机先下载并确认合并，再上传手机的汇总结果。若远端没有文件，手机可直接上传下午数据。
2. 电脑点击“下载远端数据”，再“继续预览”，到“本地数据”处理冲突并确认合并。
3. 电脑上传合并结果，手机再下载并确认合并。上传前核对远端信息；远端数据较新时先下载。

上传会覆盖指定的远端文件，不会先合并远端数据，也不保存文件历史。下载只进入预览，需确认后才修改本机。远端在预览后发生变化时，上传会被阻止；重新读取最新信息，必要时先下载合并。已有远端文件若缺少 ETag 版本标识，也不能覆盖上传。WebDAV 不自动同步或传播删除。

勾选“记住密码”后密码存入本机数据库，复制或分享数据库会带上密码；不勾选则仅保留到当前进程结束。密码不进入 JSON 数据包。HTTP 地址会明文传输密码，使用前需确认风险。

### 备份与核心数据恢复

例如，想把课程报告恢复到昨天的备份：先导出并保存今天的 JSON，再选择“恢复备份（替换核心数据）”并打开昨天的文件，核对预览中的新增、变更和删除数量，最后“确认恢复核心数据”。

恢复会按备份还原完成状态，并删除备份中没有的核心记录，包括今天新增的校对时间；它与保留双方记录的合并不同。恢复前会自动保存并校验本机副本，副本仅留在本机：电脑在数据库目录的 `operation-backups`，Android 在 `Documents/日迹`。重要备份应另行保存。

JSON 包含项目、待办、计划、实际时间块、日志、模板、计时及重复规则和例外，不包含 AI Key、ZJU 密码、Pintia Cookie、Session、token 或 WebDAV 密码。合并与恢复都保留本机设置与凭据，包括 WebDAV 配置和密码；恢复不还原这些配置，也不恢复 ZJU 缓存。

若导出或上传提示计划关联的任务已不存在，在“数据导入导出”点击“检查计划失效关联”，查看受影响计划名称、日期和关联数量后确认清除。仅移除失效关联，保留计划内容、有效关联和实际时间；修复前副本只供追溯，不能当整库备份导入。

### ZJU 与显示设置

以课程报告对应的课程为例，在“ZJU”填写凭据，先“预览任务”，核对后“导入可导入项”。课表导入先选学年、学期并“拉取并缓存校历”，再预览、导入课程日程；预览课表使用本地校历缓存，拉取校历访问 Celechron CDN。任务与课表各有撤销上次导入的按钮，按返回结果查看实际删除与跳过数量。

成绩可读取缓存或刷新，按所选重复课程口径估算；只读概览不写回学校系统。ZJU 密码和 Pintia Cookie 仅在勾选保存时保存在本机，Android 使用系统安全存储；可分别清除，不进入 JSON 数据包。

在“设置 → 界面与入口”选择导航页面和首页模块，调整时间格式或实际记录视图。开关立即生效，只隐藏内容，不删除记录；隐藏的页面可在设置中重新开启。

## 当前范围

v0.11.3 上传故障修复：历史计划的关联任务已被删除时，上传预检、确认上传和 JSON 导出现在返回可读的完整性错误，显示受影响计划名称，不再返回 Internal Server Error。在设置的“数据导入导出”点击“检查计划失效关联”，可直接查看所有受影响计划的名称、日期和清理范围，确认后仅清除已不存在的任务关联。操作先保存并校验修复前记录副本，预览过期或副本失败则不写入；不删除计划、不改变有效关联、正文或实际时间记录。该修复副本不含凭据，是记录追溯文件，不是可导入的整库备份。

- 待办：支持 DDL 类型、提醒天数、分类、关注状态、等待答复、备注和重复规则。
- 项目：可以把待办和计划日程归入同一个项目，用于承载更大的任务或目标。
- 计划日程：用于安排未来时间，保留开始/结束时间、性质、关联待办、项目、地点和备注。
- 实际时间块：用于记录已经发生的时间，支持 15/30 分钟粒度、属性与颜色、备注、关联待办或项目。
- 计时：计时结束后按时间块覆盖规则折算为实际记录，并允许在时间块界面手动修正。
- 首页：显示当前计划日程、等待答复、关注中任务、项目和临近 DDL。
- 每日日志：保存完成待办和文字日志，支持日志模板。
- 统计：按属性、待办和项目汇总实际时间块，支持单日、自然周、自然年、自定义范围和已记录时长口径。
- AI：使用用户自己的 OpenAI-compatible API Key 生成待办/计划日程草稿；草稿必须经用户确认后才写入。
- ZJU 集成：只读导入学习任务、Pintia、本科课表和成绩/学分概览。
- 数据迁移：JSON 与 WebDAV 下载共用预览、冲突选择和确认。新版数据包为 `schema_version: 0.10.0`，接受合法 `0.6.0` / `0.8.0` 旧包并跳过旧实际日程，保留重复规则例外。合并不传播删除或取消完成；恢复按备份还原完成状态。本机 WebDAV 凭据不进入数据包，也不被导入清空。
- 多端：Web、Windows Electron、Android Capacitor 本地单机版；三端通过 JSON 手动迁移数据，不做实时同步。
- WebDAV 手动汇总：下载并合并后上传结果，再让另一设备导入。只传输文件，不做账号、自动同步、后台队列或自动传播删除；保留 ETag 条件上传保护。

## 数据与隐私

- 默认使用本地 SQLite，本地单机即可运行。
- AI API Key 仅保存在当前设备；Web 使用浏览器本地存储，Android 使用系统安全存储能力。
- 后端不接收用户的 AI API Key。
- JSON 导出覆盖核心个人数据，不包含 AI API Key、ZJU 密码、Pintia Cookie、Session 或 token。
- WebDAV 密码不写入数据包、日志或错误信息；勾选记住时保存在当前设备 SQLite，未勾选时仅保留在当前会话。旧平台密码存储只用于一次迁移。
- 旧版本 `is_planned=false` 的实际日程不会自动转为时间块；升级时建议先导出备份，再使用 `scripts/clean-v010-legacy-json.py` 清洗旧包后导入。

## 本地开发运行

### 1. 启动后端

```bash
cd backend

# 首次运行时创建虚拟环境
python -m venv .venv

# Windows
.venv\Scripts\activate

# macOS / Linux
source .venv/bin/activate

pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

后端地址：`http://localhost:8000`

API 文档：`http://localhost:8000/docs`

### 2. 启动前端

```bash
cd frontend
npm install
npm run dev
```

前端地址：`http://localhost:5173`

如果 Windows PowerShell 禁止执行 `npm.ps1`，可以改用：

```bash
npm.cmd run dev
```

## 体验版构建

Windows 桌面 portable：

```powershell
.\scripts\build-desktop.ps1
```

Android debug APK，需要 JDK 21、Android SDK Platform 36 和 `ANDROID_HOME`：

```powershell
.\scripts\build-android.ps1 -AndroidSdk "C:\path\to\Android\Sdk" -JavaHome "C:\path\to\jdk-21"
```

构建产物不会提交到 Git。详细的数据目录、导入规则、已知限制和镜像参数见 `docs/build-packaging-guide.md`。

## Docker Compose 运行

```bash
docker compose up -d
```

默认 compose 偏长期自用模式：

- 前端：`http://localhost:3000`
- 后端：`http://localhost:8000`
- SQLite 数据：`${TASK_DATA_DIR:-./data}/task_app.db`

可以在项目根目录创建本地 `.env` 指定长期使用的数据目录，例如：

```env
TASK_DATA_DIR=D:/cs/task/data
```

这样即使重建镜像或升级版本，只要 `.env` 仍指向同一个目录，Docker 后端都会继续使用同一份 SQLite 数据库。

停止服务：

```bash
docker compose down
```

不要在保留本地数据时使用：

```bash
docker compose down -v
```

如果需要开发模式（前端 Vite 热更新、后端 `--reload`），使用：

```bash
docker compose -f docker-compose.dev.yml up -d
```

开发模式前端地址：`http://localhost:5173`

- AI 不越过用户确认直接创建或修改数据。
- 复杂子任务、多层级项目、看板、甘特图和复杂 RRULE 不进入 v1.0 范围。
