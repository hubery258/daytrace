# 日迹产品文档

## 产品定位

日迹是一个本地优先的个人效率工具。它的核心不是把待办简单列出来，而是帮助用户把一天里的计划、执行和复盘连起来。

当前产品适合单人自用：用户维护待办、项目和计划日程，通过计时记录实际执行，在首页关注当前最重要的事项，晚上通过今日总结回看完成情况、记录日志，并可使用自己的 OpenAI-compatible API Key 生成效率分析、复盘建议和待办/日程草稿。

## 核心原则

- 本地优先：v1.0.0 前不依赖账号体系，数据默认保存在本地 SQLite。
- 低摩擦记录：新建待办、项目和日程尽量保持轻量，不让记录本身变成负担。
- 少量关键关注：关注中的待办应保持少而重要，避免首页重新变成任务堆。
- 计划与现实并置：日程页同时保留计划日程和实际记录，方便复盘。
- 项目承载长期事项：多个待办和日程可以归入同一个项目，用来管理更大的任务或目标。
- 计时服务复盘：计时不是单纯秒表，而是生成实际日程、补齐计划与现实对照。
- 重复机制服务日常：重复任务和重复日程用于承载每天、每周、每月出现的事项。
- AI 只做辅助分析和草稿建议：AI 可以生成建议和草稿，但不替用户做不可控修改。
- 校园集成只读优先：ZJU 相关能力默认只读取和导入数据，不做自动签到、刷课、提交等写操作。

## 当前阶段目标

截至 2026-08-31，v0.8 Android 功能对齐的代码阶段已经完成：65 条客户端能力均进入可机读契约，Android 使用设备内 SQLite 独立实现项目、待办、日程、重复规则、计时、总结、模板、AI、ZJU 与备份恢复，不连接桌面 FastAPI。

自动化验证已覆盖前端 49 项、后端 22 项、Android 原生单测、lint 和 Debug APK 构建。最终实机验收与签名 release APK 仍是发布门槛，不能用模拟器或 debug 包代替。

ZJU 校历上游当前只提供 HTTP，而 Android 保持 HTTPS-only；实时刷新会明确报安全传输错误，已有缓存仍可读取。该限制不会通过全局或单域明文放行绕过。

v0.7.x 已完成的产品闭环包括：

- 待办：支持 DDL 类型、提醒天数、分类、关注状态、等待答复、备注和重复规则。
- 项目：支持把待办和日程组织进同一个项目，用于承载更大的任务或目标。
- 日程：支持计划日程、实际记录和重复日程，在同一条 0-24 点时间轴上左右对照。
- 计时：支持通过计时生成实际日程。
- 日程交互：支持拖拽创建日程和更好的日期跳转。
- 首页：显示当前日程、等待答复、关注中任务、项目和临近 DDL。
- 今日总结：保存完成待办和日志，并支持 AI 分析和 AI 单独总结。
- AI 新建：支持自然语言生成待办/日程草稿，用户确认后写入。
- 设置：保存本地 AI API Key、API 地址、模型名和提示词。
- 展示配置：页面入口和首页模块可以在设置页本地开关，只影响展示，不删除数据。
- ZJU 集成：支持学习任务、Pintia、课表、成绩和学分概览的只读读取/导入/缓存。
- 多端体验版：已经具备 Windows 桌面端体验版和 Android 体验版。
- 导入导出：支持核心个人数据的基础 JSON 导出、预览和合并导入。
- UI 与品牌：全站使用深青、琥珀、暖白和石墨视觉语言，Web、Electron 和 Android 接入日迹品牌资产。

v0.8.x 收尾聚焦两台实体设备验收、真实 ZJU/文件选择流程验证和签名 release APK；仍不引入账号同步、自动云备份或系统级提醒。

## 核心用户流程

1. 用户创建待办，按是否有 DDL、是否等待答复、是否值得关注来整理任务。
2. 用户为每天、每周、每月出现的事项创建重复任务或重复日程。
3. 用户把多个待办和日程放进项目，形成更大的推进对象。
4. 用户创建计划日程，为当天安排时间块。
5. 用户通过计时或补录记录实际执行。
6. 用户也可以使用 AI 新建，把自然语言需求转成待办/日程草稿。
7. 用户在首页查看当前日程、关注任务、项目和临近 DDL。
8. 用户完成待办后，完成记录进入今日总结。
9. 用户在日程页对照计划和实际，晚上在今日总结中写日志。
10. 用户可选择用 AI 分析当天数据，得到效率复盘和明日建议。

## 当前功能范围

### 待办

- 待办名、DDL 类型、DDL 日期、提醒天数、属性分类、状态和备注。
- 无 DDL 的待办默认进入计划箱。
- 有 DDL 的待办默认进入任务分类。
- DDL 临近状态由 DDL 日期和提醒天数自动计算。
- 等待答复状态可记录答复人。
- 关注中任务用于首页重点展示。
- 待办可以归属项目。
- 待办可以由重复规则生成。

### 项目

- 项目用于承载更大的任务或目标。
- 项目可以包含多个待办和多个日程。
- 项目支持状态、DDL、颜色和描述/备注。
- 项目完成保留人工确认，不因待办全部完成而自动完成。

### 日程与计时

- 支持计划日程和实际记录。
- 支持开始时间、结束时间、性质、关联待办、项目、地点和备注。
- 计划日程与实际记录在日程页共用一条时间轴。
- 支持计时生成实际记录。
- 支持拖拽创建计划日程或实际记录。
- 支持重复规则生成计划日程。
- 过去日期的计划日程原则上不再修改，实际记录仍可补录。

### AI

- 支持今日总结 AI 分析。
- 支持 AI 单独总结。
- 支持 AI 新建待办/日程草稿。
- 支持批量生成草稿。
- AI 草稿必须经用户确认后才写入数据。
- AI 不生成项目草稿，不越过用户确认修改数据。

### 今日总结

- 记录今日完成待办。
- 保存今日日志。
- 支持日志模板。
- 支持读取当天待办和日程数据后调用用户自己的 AI 接口生成分析。

### ZJU 集成

ZJU 集成已经从早期“脚本平台”想法收束为只读数据集成：

- 学在浙大学习任务导入待办。
- Pintia 任务导入待办。
- 本科课表导入计划日程。
- 成绩与学分本地缓存和概览。
- 所有导入都应尽量做到预览确认、去重和可撤销。

详细历史设计已归档到 `docs/archive/zju-integration.md`。

## 明确暂不做

- 通用脚本市场或任意脚本下载运行。
- 自动签到、模拟定位、刷课、自动答题、自动提交作业。
- AI 越过用户确认自动创建或修改日程。
- 复杂子任务和多层级项目。
- v1.0.0 前不做登录、多设备同步。
- v1.0.0 前不做系统级提醒。

## 重要产品决策

- ZJU 能力不做脚本平台，只保留只读和本地导入方向。
- 成绩/GPA 只做估算和概览，不作为正式成绩依据。
- AI 不应成为闲聊入口，当前职责是效率分析、复盘辅助和草稿建议。
- AI 草稿必须经用户确认后才写入数据。
- 提醒功能需要可靠运行载体，顺延到安卓端/桌面端/同步能力之后再做。
- v0.8 应优先补齐正式备份、恢复失败处理和升级兼容检查，不应扩展账号同步、系统通知或新的大型功能。
