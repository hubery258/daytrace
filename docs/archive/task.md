# MVP 上线前任务清单

## 产品目标

SimpleTasker 的 MVP 目标是做成一个单机可持续使用的个人效率面板：用户能创建待办和计划日程，在首页看到当前日程、等待答复、关注任务、临近 DDL；完成任务后进入今日总结；用户能写日志，并用自己的 AI Key 对当天执行情况做一次分析。

## 当前优先级

### P0：先让核心体验可信

1. 修正日程页时间轴展示
   - 当前问题：跨小时日程会重复显示在多个小时格里，视觉上不能表达真实持续时间。
   - 目标：日程块按开始时间定位，按持续时长决定高度。
   - 验收：一个 09:30-11:00 的日程应从 09:30 位置开始，纵向覆盖 90 分钟，而不是在 09、10、11 三个小时里重复出现。

2. 将日程页改为共轴对照
   - MVP 建议：共用一份时间轴，时间刻度放在中轴线，左侧展示规划日程，右侧展示实际记录。
   - 当前阶段：保留实际记录的手动新建/编辑/删除逻辑。
   - 下一版本：把实际记录入口逐步改成“计时页面 + 现有手动补录逻辑”。
   - 响应式约定：桌面端使用左/中/右共轴对照；移动端不要硬塞双列，改用“计划/实际”切换，同时保留同一套时间刻度语义。

3. 补齐关键业务规则
   - 关注中待办最多 3 个，前后端都要兜住。
   - 无 DDL 的任务默认进入“计划箱”或明确保留“任务”分类，二选一，不要文档和实现打架。
   - 完成待办写入今日总结时避免重复 ID。
   - 计划日程当天及未来日期可以修改，过了当天之后不可修改；规则要前后端一致。

### P1：让长期使用顺手

4. 整理设置页与 AI 配置
   - 修复设置页表单结构。
   - 增加模型名配置，避免固定为 `deepseek-chat`。
   - 增加“测试连接”按钮。

5. 完善备注展示
   - 待办和日程列表中显示备注标记或摘要。
   - 移动端不能只依赖 hover/title。

6. 增加待办分类输入补全
   - 创建待办时基于历史属性分类提供轻量补全。
   - 例：历史分类中已有“校内”，用户在属性分类输入“校”时，应提示“校内”。
   - MVP 可以先用前端 datalist 或简单下拉实现。

7. README 增加产品说明
   - 补充产品理念、核心使用流、MVP 功能边界、本地数据存储说明、AI Key 隐私说明。

### P2：上线/试用稳定性

8. 整理本地 Python 环境
   - 用户本机继续使用根目录 `.venv`。
   - Codex 使用 `backend/.codex-venv` 做后端验证，避免影响用户现有环境。

9. 整理 Docker Compose
   - 默认 compose 使用前端 Nginx 静态产物 + 后端无 reload + 固定 SQLite volume。
   - 开发模式放到 `docker-compose.dev.yml`，保留前端 Vite 热更新和后端 `--reload`。

## 暂不进入 MVP

- ZJU 脚本平台、autosign、课表爬虫、成绩/学分工具。
- AI 直接创建/修改日程或开放 MCP。
- 项目式任务拆解、子任务、循环任务。
- 备忘纸条、手机端、桌面端。
- 跨设备同步和登录。
