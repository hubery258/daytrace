# v0.5.x 重复任务与重复日程设计

## 版本定位

v0.5.x 的目标是补齐重复任务和重复日程机制，让日迹能够承载每天、每周、每月重复出现的事项。

这个版本只做“重复生成和管理”本身，不做提醒系统。提醒功能整体顺延到正式版之后，等安卓端和桌面端打包完成后，再基于更可靠的系统能力设计。

## 产品目标

- 用户可以创建重复待办。
- 用户可以创建重复日程。
- 系统能按规则生成具体待办或日程实例。
- 用户能停止、暂停或修改重复规则。
- 用户能区分重复规则和已经生成的具体实例。
- 不破坏现有普通待办、普通日程、项目和今日总结流程。

## 核心场景

### 每日习惯任务

用户创建“背单词”重复待办，规则为每天生成一次。每天出现一条具体待办，用户完成后进入今日总结。

### 每周课程或例会

用户创建每周固定时间的重复日程，例如每周三 19:00-20:00 组会。系统按规则生成计划日程。

### 每月固定事务

用户创建每月重复待办，例如月初整理账单、月底总结。

## 核心产品规则

### 规则与实例分离

重复机制应区分：

- 重复规则：描述“多久重复一次、何时开始、何时结束”。
- 具体实例：某一天实际生成出来的待办或日程。

用户完成的是实例，不是规则本身。

### 生成方式

v0.5.x 建议采用懒生成：

- 用户打开应用或进入相关页面时，系统生成当前日期附近需要出现的实例。
- 不依赖后台常驻任务。
- 避免 Web 单机环境下定时任务不可靠的问题。

建议生成窗口：

- 待办：生成今天及未来 7 天内的实例。
- 日程：生成当前查看日期所在周/月需要的实例。

具体窗口可以后续根据性能和体验调整。

### 重复范围

第一版支持：

- 每天。
- 每周，可选择星期几。
- 每月，可选择每月几号。

暂不支持：

- 每年。
- 工作日。
- 每 N 天/每 N 周。
- 复杂 RRULE。
- 节假日跳过。
- 农历。

### 修改规则

修改重复规则时，v0.5.x 第一版规则：

- 修改只影响未来未生成或未完成实例。
- 已完成实例不被修改。
- 已手动编辑过的实例成为例外实例，不再被重复规则覆盖。

### 删除规则

删除重复规则时，需要询问用户：

- 仅停止未来生成。
- 同时删除未来未完成实例。

已完成实例默认保留，避免破坏历史总结。

### 重复待办 DDL

重复待办的 DDL 由用户在创建规则时配置。

支持三种方式：

- 无 DDL：生成的实例没有截止时间。
- 实例当天某个时间：例如每天生成“背单词”，每条实例的 DDL 都是当天 23:59。
- 实例日期后 N 天：例如每周一生成“写周报”，每条实例的 DDL 是生成后 2 天。

这样可以同时覆盖习惯型任务、当天必须完成的任务和生成后延迟截止的任务。

### 项目联动

重复待办和重复日程可以归属项目。

如果规则归属某项目，则生成的实例默认继承该项目。

## 功能范围

### 重复待办

支持字段：

- 待办基础字段。
- 重复频率。
- 开始日期。
- 结束日期，可选。
- 每周星期几，可选。
- 每月几号，可选。
- 所属项目，可选。

生成出的待办实例应能正常完成、编辑、删除，并进入今日总结。

### 重复日程

支持字段：

- 日程基础字段。
- 重复频率。
- 开始日期。
- 结束日期，可选。
- 每周星期几，可选。
- 每月几号，可选。
- 所属项目，可选。

生成出的日程实例应出现在日程页，并参与重叠检测。

### 重复规则管理页或入口

可以先不新增独立导航页面。

建议入口：

- 待办创建/编辑弹窗中增加重复设置。
- 日程创建/编辑弹窗中增加重复设置。
- 设置页或汇总页增加“重复规则管理”入口。

如果实现复杂，可以先在待办汇总页或日程页提供规则列表入口。

## 建议数据模型

### recurrence_rules

```text
recurrence_rules
- id
- entity_type              # todo / schedule
- template_json            # 待办或日程模板字段
- frequency                # daily / weekly / monthly
- start_date
- end_date nullable
- weekdays nullable JSON   # [1,3,5]
- month_day nullable int
- project_id nullable
- status                   # active / paused / archived
- created_at
- updated_at
```

### 实例关联

待办和日程实例建议增加：

```text
recurrence_rule_id nullable foreign key -> recurrence_rules.id
recurrence_date nullable date
```

用于避免重复生成和追踪来源。

## API 建议

```text
GET    /api/recurrence-rules
POST   /api/recurrence-rules
GET    /api/recurrence-rules/{rule_id}
PUT    /api/recurrence-rules/{rule_id}
DELETE /api/recurrence-rules/{rule_id}
POST   /api/recurrence-rules/generate
```

说明：

- `generate` 用于懒生成当前窗口内实例。
- 页面加载待办/日程前可以触发生成。
- 后端需要保证幂等，避免重复生成同一天实例。

## 前端改动建议

- `TodoModal.jsx`：增加重复设置。
- `ScheduleModal.jsx`：增加重复设置。
- `api/client.js`：新增 recurrenceApi。
- 待办列表和日程块：展示重复来源标记。
- 待办/日程页面加载前触发懒生成。
- 可新增 `RecurrenceRuleModal.jsx` 或 `RecurrenceRuleSection.jsx`。

## 版本拆分

### v0.5.0：重复机制基础闭环

必须完成：

- 重复规则模型和 API。
- 每日、每周、每月规则。
- 重复待办生成。
- 重复日程生成。
- 幂等生成，避免重复实例。
- 实例正常参与完成、编辑、删除、日程重叠检测。

### v0.5.1：规则管理体验优化

建议完成：

- 重复规则列表。
- 暂停/恢复规则。
- 删除规则时处理未来实例。
- 更清晰的重复标记和文案。

## 验收标准

v0.5.0 完成时，应满足：

- 用户能创建每日重复待办。
- 用户能创建每周重复日程。
- 用户能创建每月重复待办或日程。
- 系统不会重复生成同一天同一规则的实例。
- 生成出的待办能完成并进入今日总结。
- 生成出的日程能显示在日程页。
- 重复日程参与现有重叠检测。
- 删除或暂停规则不会破坏已完成历史实例。

## 暂不进入 v0.5.x

- 系统级提醒。
- 浏览器通知。
- 手机通知。
- 桌面通知。
- 复杂 RRULE。
- 节假日跳过。
- AI 自动创建重复规则。

## 待确认问题

- 重复规则是否采用独立 `recurrence_rules` 表，还是直接在 todo/schedule 上加字段？
  - 已确认：使用独立 `recurrence_rules` 表。
- 懒生成窗口要多大？
  - 已确认：待办生成今天到未来 7 天；日程按当前视图生成。
- 编辑某个重复实例时，是否与规则脱钩？
  - 已确认：脱钩。手动编辑过的实例成为例外实例，不再被规则覆盖。
- 删除规则时默认是否删除未来未完成实例？
  - 已确认：弹窗询问，允许用户选择仅停止未来生成，或同时删除未来未完成实例；已完成实例默认保留。
- 重复待办的 DDL 怎么算？
  - 已确认：创建规则时由用户选择无 DDL、实例当天某个时间、实例日期后 N 天。
- 重复日程是否只生成计划日程？
  - 已确认：只生成计划日程，不生成实际记录。
- 重复规则是否可以归属项目？
  - 已确认：可以，实例继承规则的项目。
- 重复规则是否支持暂停/恢复？
  - 已确认：支持。
- 第一版是否只支持 daily / weekly / monthly？
  - 已确认：只支持每日、每周、每月。
- 重复任务是否允许 AI 创建？
  - 已确认：v0.5 不允许。
