# v0.2.x 项目功能设计

## 版本定位

v0.2.x 的目标是把日迹从“待办 + 日程 + 总结”的个人效率面板，升级为能够承载更大型事项的工具。

这个版本引入“项目”概念：用户可以把多个待办和多个日程放进同一个项目，用来管理课程大作业、开发功能、长期目标、考试准备、活动筹备等跨天推进的事项。

v0.2.x 不做复杂项目管理软件。它不是甘特图、多人协作或企业项目管理，而是为个人使用服务的轻量项目容器。

## 产品目标

- 用户能创建项目。
- 待办可以归属于一个项目。
- 日程可以归属于一个项目。
- 用户能在项目详情里看到关联待办、关联日程、进度和下一步行动。
- 项目可以被完成、暂停或归档。
- 首页仍然保持轻量，不被大型项目视图淹没。

## 核心场景

### 课程大作业

用户为一门课程的大作业创建项目，在项目下放入：

- 查资料、写提纲、完成初稿、修改、提交等待办。
- 讨论、写作、复盘等计划日程。
- 项目 DDL 和备注。

### 开发功能

用户为一个开发功能创建项目，在项目下放入：

- 调研、设计、编码、测试、写文档等待办。
- 预留开发时间块和测试时间块。
- 项目状态和下一步行动。

### 长期目标

用户为长期目标创建项目，例如考试准备、阅读计划或作品集整理，在项目下逐步放入分散任务和时间安排。

## 命名决策

界面上使用“项目”。

原因：

- “项目”比“任务组”更自然，适合描述跨天推进的大事项。
- “目标”更抽象，容易和人生目标、习惯目标混淆。
- 内部代码可以使用 `Project` 或 `TaskGroup`，但推荐与界面保持一致，使用 `Project`。

## 核心产品规则

### 归属关系

v0.2.x 第一版采用单归属：

- 一个待办最多属于一个项目。
- 一个日程最多属于一个项目。
- 一个项目可以包含多个待办和多个日程。

理由：

- 单归属更容易理解。
- 数据模型更简单。
- 后续如果确实需要多归属，可以再升级为关联表。

### 项目状态

项目建议包含以下状态：

- `active`：进行中。
- `paused`：暂停。
- `completed`：已完成。
- `archived`：已归档。
- `canceled`：已取消。

状态含义：

- 进行中项目可以在项目页和必要入口中展示。
- 暂停项目保留但弱化展示。
- 已完成项目保留复盘价值。
- 已归档项目默认隐藏。
- 已取消项目默认隐藏，处理方式可以先与归档一致。

### 项目完成

v0.2.x 采用手动完成。

系统可以提示“所有待办已完成”，但不自动把项目改为完成。项目完成往往包含主观判断，例如复盘、提交、验收、整理资料等，不能只由待办完成数量决定。

### 项目 DDL

项目可以有可选 DDL。

项目 DDL 不替代待办 DDL。它用于表达整个项目的目标截止时间，例如大作业提交日期、考试日期、功能发布目标日期。

### 项目进度

v0.2.x 的进度先用简单规则：

- 进度 = 项目下已完成待办数 / 项目下全部待办数。
- 如果项目没有待办，则显示“暂无待办”而不是 0%。
- 日程不直接计入进度，但在项目详情中展示。

后续可以加入手动进度、里程碑或权重，但不进入 v0.2.x 第一版。

## 功能范围

### 项目字段

建议新增项目实体：

- 名称，必填。
- 描述/备注，可选。
- 状态，默认进行中。
- DDL，可选。
- 颜色，可选。
- 创建时间。
- 更新时间。
- 完成时间，可选。
- 归档时间，可选。

### 待办改动

待办新增：

- 所属项目，可选。

创建/编辑待办时：

- 可以选择一个项目。
- 可以不选择项目。
- 如果从项目详情页中新建待办，默认归属当前项目。

待办列表中：

- 可以显示项目名的小标记。
- 待办汇总页可以按项目筛选。

### 日程改动

日程新增：

- 所属项目，可选。

创建/编辑日程时：

- 可以选择一个项目。
- 可以不选择项目。
- 如果从项目详情页中新建日程，默认归属当前项目。

日程页中：

- 日程块可显示项目名或项目标记。
- 不要让项目标记挤占过多日程块空间。

### 项目列表页

新增项目入口，建议放在导航栏：

- 首页。
- 日程。
- 项目。
- 待办汇总。
- 今日总结。
- ZJU。
- 设置。

项目列表页展示：

- 进行中项目。
- 暂停项目。
- 已完成项目。
- 归档项目默认隐藏，可通过筛选查看。

项目卡片展示：

- 项目名。
- 状态。
- 可选 DDL。
- 待办进度。
- 下一步待办。
- 近期日程。

### 项目详情页

项目详情页展示：

- 项目基础信息。
- 进度。
- 项目下未完成待办。
- 项目下已完成待办。
- 项目下近期日程。
- 新建待办入口。
- 新建日程入口。
- 编辑项目入口。
- 完成、暂停、归档入口。

详情页不做复杂看板。v0.2.x 第一版只需要清楚、稳定、可用。

### 首页改动

首页保持轻量。

建议只增加一个很小的“进行中项目”模块，默认展示，最多展示 3 个项目。用户后续可以在设置页关闭该模块：

- 优先展示有临近项目 DDL 的项目。
- 其次展示最近更新的进行中项目。
- 每个项目只显示名称、进度和下一步待办。

不要把项目详情搬到首页。

### ZJU 集成联动

v0.2.x 第一版不强制做 ZJU 自动项目化。

可以预留后续能力：

- 按课程自动创建项目。
- 学在浙大导入的任务自动归属到对应课程项目。
- 课表日程自动归属到课程项目。

如果 v0.2.x 做到后半段仍有余力，可以做“导入时按课程名归入项目”的轻量版本；但这不是 v0.2.0 必需项。

## 暂不进入 v0.2.x

- 多层级项目。
- 子项目。
- 甘特图。
- 看板。
- 多人协作。
- 权限。
- 项目模板市场。
- 自动排程。
- AI 自动拆解项目。
- 项目预算、文件、评论等重型管理能力。

## 建议数据模型

### projects

```text
projects
- id
- name
- description
- status
- ddl_date
- notes
- completed_at
- archived_at
- created_at
- updated_at
```

### todos

新增：

```text
project_id nullable foreign key -> projects.id
```

### schedules

新增：

```text
project_id nullable foreign key -> projects.id
```

### 迁移策略

当前项目使用轻量 SQLite 兼容迁移。v0.2.x 可以继续使用 `PRAGMA table_info + ALTER TABLE` 风格增加字段。

如果后续项目功能继续增长，再评估 Alembic 或正式迁移工具。

## API 建议

新增项目接口：

```text
GET    /api/projects
POST   /api/projects
GET    /api/projects/{project_id}
PUT    /api/projects/{project_id}
DELETE /api/projects/{project_id}
GET    /api/projects/{project_id}/overview
```

说明：

- `DELETE` 允许硬删除，但前端需要二次确认。归档仍然作为常规收纳操作保留。
- `overview` 返回项目详情页所需的聚合数据，包括待办、日程、进度和下一步行动。

待办和日程接口：

- 创建和更新时支持 `project_id`。
- 列表查询支持按 `project_id` 过滤。

## 版本拆分

### v0.2.0：项目基础闭环

必须完成：

- 项目模型和 API。
- 项目列表页。
- 项目详情页。
- 创建、编辑、完成、暂停、归档项目。
- 待办归属项目。
- 日程归属项目。
- 从项目详情页新建待办和日程。
- 项目进度展示。

### v0.2.1：主流程整合

建议完成：

- 首页进行中项目模块。
- 设置页支持关闭首页项目模块。
- 待办汇总页按项目筛选。
- 日程页显示项目标记。
- 项目详情页体验优化。

### v0.2.2：ZJU 与项目的轻量联动

可选完成：

- 按课程名创建或匹配项目。
- ZJU 学习任务导入时可归属课程项目。
- ZJU 课表导入时可归属课程项目。

如果实现成本高，可以顺延到后续版本。

## 验收标准

v0.2.0 完成时，应满足：

- 用户能创建项目。
- 用户能把待办加入项目。
- 用户能把日程加入项目。
- 用户能从项目详情页看到项目下的待办和日程。
- 用户能从项目详情页新建待办和日程，并默认归属当前项目。
- 用户能看到项目进度。
- 用户能暂停、完成、归档项目。
- 非项目待办和非项目日程仍能正常使用。
- 旧数据在迁移后不丢失。

## 风险与注意事项

- 不要让项目功能把首页变重。
- 不要过早引入多归属、多层级、看板、甘特图。
- 项目完成必须保留人工确认。
- 项目 DDL 和待办 DDL 要并存，不要互相覆盖。
- ZJU 课程项目化很诱人，但不要让它阻塞 v0.2.0 基础闭环。

## 待确认问题

- 项目删除是否允许硬删除，还是只能归档？
  - 已确认：允许硬删除，但前端需要二次确认；归档作为常规收纳操作保留。
- 项目状态是否需要“取消”或“放弃”？
  - 已确认：可以有“取消”状态，第一版可以按归档类似方式处理，默认隐藏。
- 首页进行中项目模块是否默认展示，还是允许用户在设置中关闭？
  - 已确认：默认展示，也允许在设置页关闭。更通用的页面/模块显示控制放入 v0.7.x。
- 项目是否需要颜色或图标？
  - 已确认：不需要图标，可以有颜色。
- 项目是否需要独立备注，还是描述已经足够？
  - 已确认：先使用单个“描述/备注”字段，既可以写项目说明，也可以记录推进过程中的补充信息。暂不拆成两个字段。
- 项目 DDL 是否应该进入首页 DDL 临近模块？
  - 已确认：应该进入。
