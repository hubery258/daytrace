# v0.7.5 Debug & Hardening

## 版本定位

v0.7.5 是进入 v0.8 正式备份恢复前的小修复版本。目标是处理 `docs/debug.md` 中已经积累、但不需要改变产品方向的轻中度 bug，提升数据可信度和日常使用顺滑度。

v0.7.5 不做新功能扩张，不做账号同步，不做系统级提醒，不做 UI 大改。

## 优先级

### P0：数据正确性

优先处理会影响用户判断或历史记录可信度的问题：

- ZJU 导入 DDL 不正确。
- 当前日程偶尔不显示或显示错误，重点排查时区和日期范围查询。
- 跨天日程显示问题。
- 今日完成待办不显示。
- 任务完成后前端不刷新，完成状态和今日总结记录不一致。

### P1：流程阻塞

处理会卡住流程或明显打断使用的问题：

- 计时页面取消后卡住，无法继续下一次计时。
- 手机端新建任务/日程弹窗不要自动弹出输入框。
- 短时段日程文字显示异常。

### P2：体验修正

不阻塞使用，但适合顺手修：

- 项目“下一步做”排序不合理，应优先考虑手动顺序、DDL、创建时间，而不是简单按加入时间。
- 周视图展示课程地点和备注；导入课程时把教室写入地点字段。
- DDL 时间选择的 12/24 小时制问题可先记录，若实现成本高可顺延到 v0.9。

## 与 v0.8 的关系

`docs/debug.md` 中的“备份的导入与删除逻辑”应和 v0.8 设计一起处理，不建议在 v0.7.5 仓促改成复杂恢复系统。

v0.7.5 可以先做：

- 确认当前导入逻辑不会误删本地数据。
- 给现有导入失败补清晰提示。
- 记录 v0.8 需要支持“合并导入”和“完整恢复”两种模式。

## 建议执行方式

1. 先读取 `docs/debug.md`。
2. 把问题按 P0 / P1 / P2 分类。
3. 每修一个问题，补充复现步骤、修复说明和验证结果。
4. 优先跑前端构建；涉及后端时跑后端语法检查。
5. 不要顺手重构大模块，不要把 v0.8 备份恢复一次性做完。

## 验收标准

v0.7.5 完成时应满足：

- P0 问题已修复或有明确不可修原因。
- P1 问题不再阻塞常用流程。
- `docs/debug.md` 中已处理项有标记或迁移说明。
- Web / Windows / Android 至少完成相关页面的手动验证。
- 不引入账号同步、系统通知或新的大型功能。

## 实现状态（2026-08-16）

- P0、P1 和 P2 条目均已完成代码修改。
- 项目待办增加可选手动顺序；未设置时继续按 DDL 和创建时间自动排序。
- DDL 时间输入增加 12/24 小时制偏好和显式时间控件。
- 数据导入提供“合并导入”和“完整恢复”；完整恢复显示删除预览、先生成本机安全备份，再在事务中替换。
- 后端回归测试和前端构建检查留作基础验证；Web、Windows、Android 手动验收由用户执行。
- Android 全功能对齐不扩入本修复版本，后续工作见 `docs/v0.8-mobile-feature-parity.md`。

## v0.8 后续说明（2026-08-31）

v0.7.5 在这里保留为历史基线。其后 v0.8 已完成 Android 双适配器、重复规则、计时/AI/备份与 ZJU 代码对齐，并通过自动化构建；实体设备矩阵与签名 release 仍未完成。

后续状态以 `docs/v0.8-mobile-feature-parity.md` 和 `docs/v0.8-android-acceptance.md` 为准。
