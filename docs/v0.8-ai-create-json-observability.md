# v0.8 AI 新建 JSON 可观察性与 Prompt 更新

## 问题

AI 新建依赖模型返回结构化 JSON。当前如果返回内容不可解析，用户只看到“AI 返回的内容不是可解析的 JSON，请重试”，不知道模型实际返回了什么，也不知道是多了 Markdown、字段缺失、时间格式错误，还是 prompt 已经过时。

这会导致用户无法判断是自己的输入问题、模型问题、API 兼容问题，还是应用解析器问题。

## 需要改进

### 1. 解析失败可观察

当 AI 草稿解析失败时，界面应展示：

- 失败原因：例如非 JSON、缺少 `type="drafts"`、`items` 不是数组、字段不可解析。
- AI 原始返回内容 raw response，放在可折叠区域或“查看 AI 原文”按钮中。
- 如果应用曾从 Markdown/code fence 中提取 JSON，也应显示“提取后的 JSON 片段”。
- 提供“复制原文”和“复制错误信息”按钮，方便反馈。

不要把 raw response 写入数据库；只在当前页面状态中临时展示。

### 2. Parser 返回更完整诊断

`parseAiDraftResponse` 建议返回：

```js
{
  drafts: [],
  errors: [],
  warnings: [],
  rawText,
  extractedText,
  parseError,
  parsedType
}
```

前端页面根据这些字段展示失败详情。

### 3. Prompt 需要更新

当前 `AI_DRAFT_SYSTEM_PROMPT` 仍写着 `v0.5.x`，需要改成不绑定旧版本，或改成当前规则版本。

重点更新：

- 明确“只输出一个 JSON object，不要 Markdown/code fence”。
- 给出最小可用示例。
- 明确未知字段不要输出。
- 明确日期必须是本地时间 `YYYY-MM-DDTHH:mm:ss`。
- 明确不能生成项目草稿。
- 重复规则是否允许 AI 创建，应以当前产品决策为准；若仍不允许，删掉 `v0.5.x` 字样，改成“当前版本不允许”。

### 4. 覆盖所有 AI 草稿入口

至少检查：

- `AiCreatePage.jsx`
- `DailySummaryPage.jsx` 的明日草稿
- `ProjectDetailPage.jsx` 的项目下一步
- `SchedulePage.jsx` 的空档安排

这些入口都应在解析失败时能展示原始返回内容。

## 不做

- 不让 AI 自动写入数据库。
- 不引入后端代理或云端 prompt 服务。
- 不把失败 raw response 长期保存到日志或备份包。
- 不在这个任务里重做整个 AI 对话体验。

## 验收

- 模型返回 Markdown 包裹 JSON 时，能提取并解析。
- 模型返回非 JSON 文本时，用户能看到原始返回内容。
- 模型返回 JSON 但字段不合法时，用户能看到具体字段错误。
- 所有 AI 草稿入口解析失败时表现一致。
- 当前 prompt 中不再出现过时版本字样，例如 `v0.5.x`。
