# v0.11.3 合并逻辑专项审查（2026-10-11）

## 已修复

1. 拆分后合并方向不对称：原块在本机、旧拆分片段来自另一端时，移动前后的版本可能同时保留。新增反向原块/片段身份冲突识别，两端均要求明确选择；保留另一来源的非冲突时间，预览展示双方区间。四组共享场景覆盖双向导入及两种选择，断言实际统计分别为 30 或 45 分钟，重复导入不增加记录。
2. 本机断裂关联被导出静默过滤：现在导出前检查项目、任务、计划、实际块、日志、计时及重复例外的整数关联；标量和数组关联不存在时明确报错，禁止生成不完整预览或操作前副本。合法旧实际日程的排除仍保持兼容。
3. 重复例外只按规则/日期匹配：改为 UUID 优先，保留同规则/类型/日期不同 UUID 的去重后备。相同 UUID 改日期计为更新，完整选择版本。有效日期互换在事务内先重建变化的例外行，保留 UUID、创建时间及全部业务内容，避免临时唯一约束冲突；例外整数 ID 没有入站业务引用。额外注入失败验证整批回滚。

4. 正常本机删除留下断裂引用：删除任务清理计划、日志、重复模板、实际时间和计时关联；删除计划清理计时来源关系；删除项目清理实际时间和计时等项目关联。Android 在单次事务中执行删除与清理，电脑在既有 CRUD 事务中完成；重复规则批量删除未来实例也复用引用清理。已有正文、时间区间和其余业务记录保留。此处理仅在明确本机删除时触发，不通过合并传播删除。

## 预览过期保护

未发现新的绕过路径。新增测试分别替换数据包内容、用户选择和合并/恢复模式，旧 token 均被拒绝且数据不变；已有测试保留本地修改后拒绝、破损数据拒绝、事务中途失败和副本失败保护。本机关联在预览后损坏也会阻止执行，不会静默清空关系。

使用前端实际 mobileDatabase 调用路径和后端实际预览/执行接口，所有数据库和副本均在测试目录中。共享场景从 20 增至 28，新增拆分双向选择、例外改日期、同日不同 UUID 去重及日期互换，并增加包含全部主要关联的往返场景。

前端完整 124 项、Android 数据路径 80 项和生产构建通过。最终后端完整 77 项通过，结果记录在 release/backend-review-complete-v0.11.3.log，包含关联清理与故障专项。未操作用户真实数据库或 WebDAV，未 pull、commit 或 push。

专项审查后已重新构建 v0.11.3 Android debug APK 与 Windows portable，包含全部修复。重打后端在独立 SQLite 中通过双向拆分、例外日期互换及完整关联重复导入的 HTTP 验收；APK 和 Windows 前端资源逐文件匹配最新 dist，桌面内置后端与最新 sidecar 二进制一致。产物 SHA256 见 release/build-info-0.11.3.json。实体设备原生文件读写、GUI 和真实网络故障仍未验证。

## 2026-10-12 历史计划关联修复入口

上传校验暴露了旧版删除任务后残留的计划关联。新增设置中的“检查计划失效关联”，直接列出名称、起止日期、将移除的失效关联数和保留的有效关联数。用户确认后，在事务内重新检查计划和任务状态，校验预览 token，并在任何修改前保存、读回校验修复前记录；仅更新受影响计划的 linked_todo_ids，不改变时间、名称、正文、有效关联、任务完成状态、实际时间或凭据。修复记录副本有独立 app/kind 标记，不作为可导入的整库备份。

Web/Windows 与 Android 实际界面调用相同接口流程；Android 实际及模块化路径共用修复处理器。重复修复无修改，旧预览、未确认、副本失败和事务中途写入失败均不清理数据。前端完整 127 项、同步专项 88 项、接口契约 7 项及后端修复专项 3 项通过；没有对真实数据库执行修复或访问真实 WebDAV。
