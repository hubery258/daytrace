# v0.8 Android 功能全量对齐计划

## 版本目标

v0.8 的唯一主目标是把 Android 从“核心功能体验版”升级为“功能完整的本地单机版”：凡是 Windows/Web 单机版可以完成的用户流程，Android 都应能够完成，并保持相同的数据语义、错误提示和导入导出格式。

“功能对齐”不是让 Android 连接桌面端后端，也不是引入账号或云同步。Android 继续使用设备内 SQLite；需要访问外部服务的功能通过受控的原生网络适配器实现。

## 完成定义

- `frontend/src/api/client.js` 暴露的业务能力在 Android 均有可工作的实现，不再返回“体验版暂不支持”或空成功结果。
- 同一操作在 FastAPI/SQLite 与 Android/SQLite 上具有一致的校验、排序、事务和错误语义。
- 项目、待办、日程、重复规则、计时、总结、模板、AI、ZJU、备份恢复九类流程均能在 Android 独立完成。
- Android 关闭页面或重启应用后，进行中的计时、重复规则和本地数据仍可正确恢复。
- 不把 ZJU 密码、Cookie、AI Key 或完整个人备份静默发送到新的远端服务。

## 技术路线

### 1. 建立双数据适配器契约

把 `client.js` 中所有路径整理成可机读的能力清单，并为每条能力声明：请求方法、输入字段、返回结构、错误码/错误文案、是否必须事务化。

- 桌面/Web 适配器：继续调用 FastAPI。
- Android 适配器：继续调用 `mobileDatabase.js`，但拆分为 projects、todos、schedules、recurrence、timer、logs、portability、zju 八个模块。
- 共享纯函数：日期解析、DDL 判断、下一步排序、范围相交、重复日期生成、导入包校验应只保留一份可复用实现。
- 契约测试使用同一组场景分别运行两个适配器，避免“接口存在但行为不同”。

### 2. 补齐重复规则引擎

这是当前最大本地功能缺口，应作为 P0 首先完成。

- 在 Android 建立 `recurrence_exceptions` 表和版本迁移。
- 实现规则 create/get/list/update/delete/generate。
- 实现从待办、日程实例同步所有未来实例。
- 支持仅修改/删除当前实例，并记录例外，后续生成不得复活。
- 对齐 daily/weekly/monthly、开始/结束日期、星期、每月日期、DDL offset/fixed-date 等现有语义。
- 生成过程放在单个 SQLite 事务中，并保证重复调用幂等。

### 3. 收敛项目、待办与日程行为差异

- 把后端 Pydantic 校验对应为共享前端校验，覆盖关注上限、DDL 必填、等待答复人、结束时间晚于开始时间等规则。
- Android 实现计划日程冲突检测及与桌面端相同的提示/覆盖行为。
- 对齐项目删除时待办、日程解除关联的行为。
- 对齐手动顺序、DDL、创建时间的项目“下一步做”排序。
- 为跨天、边界时刻、北京时间和旧 UTC 数据建立迁移/兼容用例。

### 4. 激活 Android ZJU 全流程

不在 Android 内启动 Python/FastAPI sidecar，也不增加中转服务器。将 ZJU 网络逻辑迁移为独立的 TypeScript 服务层，并通过 Capacitor 原生 HTTP 能力处理 Cookie、重定向和 WebView CORS 限制。

- 凭据：密码、Pintia Cookie、Session 等进入 Android Keystore 支持的安全存储；普通 SQLite 和 JSON 备份不得包含这些字段。
- DDL：实现 Courses 与 Pintia 拉取、北京时间转换、预览、去重、导入和撤销。
- 课表：实现校历缓存、课表拉取、节次展开、教室地点、导入和撤销。
- 成绩：实现缓存读取、拉取、清理和奖学金/培养方案两种统计口径。
- 网络：统一超时、取消、证书错误、登录失效、重定向异常和离线提示。
- 安全边界：继续只读学校数据，不增加签到、提交、选课、答题等写操作。

### 5. 完成计时、AI 与应用生命周期

- 应用进入后台、被系统回收、重启后，按持久化时间戳恢复计时，不依赖常驻 JavaScript 定时器。
- 开始/暂停/继续/完成/取消均使用执行锁，并在成功或失败后重新读取当前计时。
- Android 直接 AI 请求改用统一网络适配器，处理超时、取消、无网和证书错误。
- AI Key 保持设备本地，不进入业务数据库、日志或备份包。
- 本版本不新增系统常驻通知；若后台计时必须依赖前台服务，再单独评估通知权限和耗电成本。

### 6. 数据与文件能力收尾

- Android 文件选择器可以读取 JSON；手动导出可保存或分享；恢复前安全备份仅写入本机 Documents/日迹。
- 合并导入永不删除本地数据；完整恢复必须显示逐实体新增、覆盖、删除数量。
- 完整恢复必须事务化，任何字段或引用错误都回滚。
- 升级旧 Android 数据库时逐版本执行迁移，不再只依赖 `CREATE TABLE IF NOT EXISTS`。
- 对大数据包、损坏 JSON、旧 schema、磁盘空间不足、用户取消文件操作建立明确提示。

## 里程碑

### M0：能力清单与契约测试框架

- 固化所有 API 路径和行为矩阵。
- 建立桌面适配器与 Android 适配器的共享场景测试。
- 禁止 Android 对未实现写操作返回伪成功。

### M1：本地核心能力 100%

- 完成重复规则引擎。
- 收敛项目、待办、日程校验和事务差异。
- 完成数据库版本迁移框架。

### M2：计时、总结、AI 与文件流程

- 完成计时生命周期恢复。
- 完成模板、总结、AI 上下文和网络错误对齐。
- 完成备份、合并导入、完整恢复的 Android 实机流程。

### M3：ZJU 全量激活

- 完成原生 HTTP、Cookie/重定向处理和安全凭据存储。
- 完成 DDL、课表、校历、成绩、缓存、导入与撤销。

### M4：实机验收与发布

- 至少覆盖一台 Android 低版本设备和一台当前版本设备。
- 完成冷启动、后台恢复、无网、权限拒绝、磁盘不足和升级安装测试。
- 生成 release APK，并更新构建说明、数据安全说明和已知限制。

## 验收矩阵

每个模块至少验证以下维度：

1. 新建、读取、编辑、删除。
2. 应用重启后的持久化。
3. 空数据、非法输入、重复点击和并发操作。
4. 北京时间、跨天、结束边界和旧数据格式。
5. 导出后在桌面导入、桌面导出后在 Android 导入。
6. 操作失败后无半写入、无伪成功、无必须手动刷新才能恢复的状态。

发布门槛：`client.js` 的功能清单除平台明确不存在的能力外全部通过；代码中不再出现“安卓体验版暂不支持”或针对正常功能的空实现。

## 明确不做

- 账号、云同步、后台同步队列和多端冲突解决。
- 自动云备份或把完整个人数据上传到新服务。
- 系统级 DDL/日程通知；除非后台计时的前台服务技术上必须展示通知。
- ZJU 自动签到、提交作业、选课、答题等学校系统写操作。
- 为了复用 Python 代码而在 Android 内嵌完整 FastAPI 服务。
