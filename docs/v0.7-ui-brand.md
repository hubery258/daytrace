# v0.7.x UI、交互与品牌感升级

## 版本定位

v0.7.x 的目标是让日迹从“功能可用”走向“像一个有自己味道的产品”。这个版本不扩展账号同步、系统级提醒或新的大型功能，而是集中打磨 UI、交互、品牌识别和设置页页面/模块开关。

当前产品核心已经稳定：待办、项目、日程、计时、今日总结、AI 草稿、ZJU 只读集成、重复规则、多端体验版和 JSON 导入导出。v0.7 应围绕这些既有能力建立统一的表达方式。

## 设计关键词

- 安静：界面不抢用户注意力，减少高饱和色和过多装饰。
- 清晰：首页、日程、待办、项目都应有明确的信息层级。
- 日常感：日迹是每天会打开的工具，不是一次性的展示页。
- 计划与现实并置：这是日迹区别于普通 todo / calendar 的核心气质。
- 本地可信赖：数据在本地、动作可确认、错误可理解。

## Logo 方向

当前推荐优先使用“日期格 / 日出 / 路径轨迹”的方向继续打磨。

已生成概念图：`frontend/src/assets/brand/riji-logo-concept-b.png`。

这个方向的含义：

- 日期格代表一天和日程容器。
- 日出代表每日开始、复盘后的重新出发。
- 路径轨迹代表计划、执行和留下的痕迹。
- 琥珀色适合表达“今日”和温度，深青绿色适合表达行动轨迹，石墨色适合表达可靠和克制。

后续处理建议：

- 先保留为概念源图，不直接当最终商用 Logo。
- 如需正式使用，应重绘为 SVG 或矢量源文件。
- Android launcher icon 需要再生成 mdpi/hdpi/xhdpi/xxhdpi/xxxhdpi 或使用 Android Studio Image Asset 重新导出。
- 桌面端图标需要再输出 `.ico`。
- Web 端需要补 favicon / apple-touch-icon 等尺寸。

## UI 风格方向

建议避免泛效率工具常见的蓝紫渐变、大量悬浮卡片和 SaaS 后台感。日迹更适合克制、稳定、略带温度的个人工具界面。

建议基线：

- 主色：深青绿，用于主要行动、轨迹、当前状态。
- 辅色：温暖琥珀，用于今日、完成、复盘和轻量强调。
- 中性色：石墨黑、灰蓝、暖白背景，减少纯黑纯白造成的割裂。
- 圆角：中等圆角即可，避免所有东西都变成大胶囊。
- 卡片：用于承载具体事项，不把整页 section 都做成漂浮卡片。
- 字体层级：页面标题、模块标题、事项标题、辅助信息要清楚区分。
- 状态表达：关注中、等待答复、临近 DDL、计划日程、实际记录要有稳定颜色和图标语义。

## v0.7 建议拆分

### v0.7.0：视觉基础统一

目标：建立全局视觉语言。

建议任务：

- 整理全局 CSS 变量或设计 token：颜色、间距、圆角、阴影、字体大小、边框。
- 统一按钮、输入框、选择器、弹窗、卡片、标签、空状态和错误提示。
- 统一导航栏视觉，减少页面之间的拼接感。
- 避免一次性重写业务逻辑。

验收：主要页面看起来属于同一个产品，而不是多个阶段拼出来的页面。

### v0.7.1：核心页面交互优化

目标：优化每天最常用的路径。

建议任务：

- 首页：强化“现在该看什么”的扫描效率，控制模块密度。
- 待办：创建、编辑、完成、关注、等待答复的操作更顺手。
- 项目：项目卡片和详情页突出下一步行动，而不是堆信息。
- 日程：计划/实际两列对照更清楚，小屏下减少拥挤。
- 今日总结：日志、完成项和 AI 区域层次更自然。

验收：新增一个待办、安排一个日程、完成并复盘一天的流程明显更顺。

### v0.7.2：品牌资产接入

目标：把 Logo 和基础品牌元素接进产品体验。

建议任务：

- 基于概念图重绘或清理正式 Logo。
- 接入 Web 顶部导航或侧边导航品牌位。
- 准备 Web favicon、桌面端图标、Android launcher icon。
- 优化空状态：不要大篇解释功能，可以用轻量图形和短文案表达当前状态。
- 检查深浅背景、不同尺寸下的 Logo 可读性。

验收：用户能通过图标和首页第一屏感到“这是日迹”。

### v0.7.3：页面/模块开关

目标：允许用户按需要裁剪入口和展示。

建议任务：

- 设置页新增页面开关：例如首页、日程、待办、项目、计时、今日总结、ZJU、设置。
- 设置页新增首页模块开关：例如当前日程、等待答复、关注任务、项目、临近 DDL。
- 设置页新增页面内模块开关：优先覆盖 ZJU 和首页，不要一开始做成复杂布局编辑器。
- 开关只影响导航入口和展示，不删除数据。
- 至少保留设置页入口，避免用户把自己锁死。

验收：非 ZJU 用户可以隐藏 ZJU 页面；不常用项目的用户可以关闭首页项目模块；数据仍保留。

### v0.7.4：跨端视觉与交互检查

目标：确保 v0.7 改造没有破坏 Web、桌面端和 Android 体验版。

建议任务：

- Web 浏览器核心流程检查。
- Windows Electron 体验版启动和核心页面检查。
- Android 小屏下首页、待办、日程、设置页检查。
- 检查 Logo、图标、颜色和布局在不同尺寸下是否稳定。
- 补充已知限制和截图记录。

验收：三端主要页面没有明显布局错乱，核心流程可用。

## 明确不进入 v0.7

- 账号登录和多端同步。
- 系统级提醒、通知、后台常驻提醒。
- 自动云备份。
- 复杂主题市场或皮肤系统。
- 看板、甘特图、多层级项目。
- 复杂 RRULE、节假日跳过、农历重复。
- AI 自动越过确认写入数据。
- ZJU 自动签到、刷课、答题、提交等写操作。

## 执行建议

不要一口气全站重做。建议先做两个样板页面：

1. 首页：决定信息密度、卡片、颜色、状态表达和品牌露出。
2. 设置页：决定表单、开关、分组、说明文案和页面/模块开关交互。

样板确认后，再扩展到日程、待办、项目、今日总结和 ZJU。这样能避免 UI 改造变成漫无边界的重构。

## 实施结果（2026-08-11）

v0.7.x 已完成并进入收尾状态：

- 建立深青、琥珀、暖白、石墨为核心的设计 token，并保留旧页面变量别名以降低改造风险。
- 首页形成“此刻、正在关注、临近 DDL、项目、等待答复”的扫描层级；硬性与弹性 DDL 使用轻量标识。
- 首页格言、空状态和本地数据提示体现安静、日常、计划与现实并置、本地可信赖的产品气质。
- 设置页加入导航页面与首页模块开关，配置保存在本机 `localStorage`，只控制入口和展示，不删除数据。
- 全站页面、项目卡片、计划/实际日程、计时、总结、AI、ZJU、弹窗和移动端规则统一到同一视觉语言。
- 概念 B 已重绘为 SVG；Web favicon、Electron `.ico`、Android legacy/adaptive launcher icon 已接入。
- 应用体验版版本升级为 `0.7.4`；JSON 数据包 `schema_version` 仍为 `0.6.0`，因为 v0.7 未改变数据模型。

### 验证结果

- `npm.cmd run build` 通过。
- Windows Electron portable 构建通过。
- Android debug APK 构建与 v2 调试签名验证通过。
- 用户完成桌面端与 Android 基础体验，未发现需要在 v0.7.x 阶段阻断发布的 UI 问题。

### 已知限制

- 当前仍是未正式签名的 Windows portable 与 Android debug 包，不用于应用商店发布。
- 页面开关是展示偏好，不是权限控制；被隐藏页面仍保留数据和直接路由。
- 业务问题继续记录在 `docs/debug.md`，按 v0.8/v0.9 优先级处理，不在 v0.7 收尾阶段扩展范围。
